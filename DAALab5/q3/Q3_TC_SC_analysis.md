# Q3 — Quick Sort (File-Based): Time & Space Complexity Analysis

## Algorithm used: Quick Sort (Lomuto partition, last element as pivot)

### Time Complexity

Quick Sort's runtime is governed by how evenly `partition` splits the
array at each step.

**Recurrence:**

    T(N) = T(k) + T(N - k - 1) + O(N)

where k is the number of elements ≤ pivot after partitioning.

| Case | Split | Recurrence | Time Complexity |
|---|---|---|---|
| Best case | Perfectly balanced (k ≈ N/2) | T(N) = 2T(N/2) + O(N) | **O(N log N)** |
| **Average case** | Random/uniform input | T(N) = T(N/4)+T(3N/4)+O(N) (typical) | **O(N log N)** |
| Worst case | Maximally unbalanced (k = 0 or N−1 every time, e.g. already-sorted input with last-element pivot) | T(N) = T(N-1) + O(N) | **O(N²)** |

Since the data here is *random* (generated by the program itself), the
worst case (already sorted / reverse sorted input) essentially never
occurs, so the **expected behaviour is O(N log N)**.

Additional (linear) costs:
- File generation: O(N)
- File read: O(N)
- File write: O(N)

These do not change the overall asymptotic complexity, which remains
dominated by the sort itself: **O(N log N) average, O(N²) worst case.**

### Space Complexity

- The array of N integers: **O(N)** (required to hold the data in memory).
- Quick Sort sorts **in place**, so no extra array is needed beyond the
  input array itself → O(1) *additional* space for data.
- Recursion stack:
  - Average case: O(log N) (balanced recursion tree)
  - Worst case: O(N) (degenerate recursion chain)

**Overall:** O(N) space (to hold the array), O(log N) additional
average-case stack space.

### Summary Table

| Metric | Value |
|---|---|
| Time (Average) | O(N log N) |
| Time (Worst) | O(N²) |
| Time (Best) | O(N log N) |
| Space (Array) | O(N) |
| Space (Recursion stack, avg) | O(log N) |
